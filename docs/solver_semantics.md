# 求解语义

## 理论与离散

* 单元：4 节点双线性等参四边形 Q4，采用 2×2 高斯积分组装刚度；
* 本构：
  * `CPS4` 平面应力：
    `D = E/(1-ν²) · [[1,ν,0],[ν,1,0],[0,0,(1-ν)/2]]`，按厚度 `t` 缩放；
  * `CPE4` 平面应变：
    `D = E/((1+ν)(1-2ν)) · [[1-ν,ν,0],[ν,1-ν,0],[0,0,(1-2ν)/2]]`。
* 全局自由度按紧凑节点索引排布为 `[ux0, uy0, ux1, uy1, ...]`。

## 求解流程

1. **校验与归一化**：严格校验（见 `input_format.md`），生成连续数组与
   0 基紧凑索引；计算与输入顺序无关、与求解器版本绑定的模型哈希。
2. **组装**：逐单元累加全局刚度矩阵 `K`，每
   `checkpoint_interval` 个单元产生一次可恢复检查点；最终对 `K`
   做对称化以消除累加顺序的舍入非对称。
3. **约束处理**：将自由度划分为指定位移集 `p` 与自由集 `f`，求解缩减系统
   `K_ff · u_f = f_f − K_fp · u_p`，因此非零指定位移被严格满足。
4. **线性求解**：`numpy.linalg.solve` 对正定（约束充分）系统做确定性
   消元；奇异系统返回 `singular_matrix`。
5. **反力恢复**：约束自由度反力 `R_p = K_pu · u − f_p`。
6. **应力恢复**：在每个单元形心计算 `σ = D · B · u_e`
   （σxx, σyy, σxy），并按平面应力（σzz=0）或平面应变
   （σzz=ν(σxx+σyy)）给出 von Mises 等效应力。

## 整体力平衡与残差

在全部**自由自由度**上计算不平衡力：

```
r = K_ff u_f + K_fp u_p − f_f
```

`max|r|` 必须不超过阈值

```
tolerance_effective = equilibrium_tolerance
                    · max( max|f_applied| , residual_force_scale )
```

默认 `equilibrium_tolerance = 1e-6`，`residual_force_scale = 1.0`，
因此即便载荷很小或为零也仍有绝对力下限。超过阈值返回
`equilibrium_not_satisfied`，作业标记为 `failed` 且**不产出结果**。
约束方向的支座反力与外载荷满足整体平衡
`Σ f_applied + Σ R = 0`（双分量分别成立，误差在浮点量级）。

## 确定性与版本绑定

* 模型哈希对输入做规范化：实体按整数 id 排序后以紧凑、键有序的 JSON
  序列化再取 SHA-256，故**列表顺序不影响哈希**，但任何节点/单元/材料/
  约束/载荷/选项的语义变化都会改变哈希。
* 哈希中包含输入 schema 版本与求解器版本（`SOLVER_VERSION`）。求解语义
  或输出格式发生不兼容变化时必须提升 `fem/models.py` 中的
  `SOLVER_VERSION`，旧缓存不会被误当作新结果返回。
* 相同模型与参数：固定的单元遍历顺序、自由度顺序与 numpy 消元保证浮点
  结果在同一平台跨进程/跨重启**逐位可复现**。作业完成后，相同模型再次
  提交将直接返回已完成作业（不重复求解）。

## 输出 `SolveResults`

* `displacements[]`：`{node, ux, uy}`，按原始节点 id；
* `stresses[]`：`{element, sxx, syy, sxy, von_mises}` 形心应力；
* `reactions[]`：每个受约束节点一条 `{node, fx, fy}`（未约束分量为 0）；
* `residual`：`{max_abs_residual, node, dof, tolerance}`；
* `solver_version`、`model_hash`：版本绑定信息。

## 检查点与恢复

* 作业快照（状态、进度、错误、完成结果）以 `写临时文件 → fsync → 原子
  rename` 方式落盘，崩溃只会留下上一份完整文件或新一份完整文件，不会
  出现可被误认为结果的截断内容。
* 组装阶段每 `checkpoint_interval` 单元把部分刚度矩阵原子写入
  `<job>.K.npy`，并在快照中记录 `assembled_through`。进程重启后，处于
  `running` 的未完成作业从最近检查点**继续组装**，随后对完整系统求解并
  做平衡校验，因此续算结果与一次算完完全一致。
* `completed` 作业重启后保持可查询，不重新求解；其部分矩阵在完成时即
  删除。损坏/形状不符的检查点被安全丢弃并从组装起点重算。
* `failed`/`cancelled`/`timeout` 作业不携带任何结果载荷，其大矩阵也被
  立即清理，绝不留下可误认为有效结果的部分输出。

## 并发、取消与超时

* 固定大小的线程池（`worker_threads`）并发运行阻塞求解；每个作业有独立
  状态与取消事件，互不共享可变结果。
* 取消是协作式的：组装检查点与求解边界轮询取消事件。队列中尚未开始的
  作业可立即取消；任一作业取消、超时或失败不影响其他作业。
* 超时在组装检查点与求解边界检查；触发后作业为 `timeout`，无结果。
